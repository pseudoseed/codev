## Two defects in that commit are worth putting side by side

Both are the same shape — **a fix that cannot fire** — and Phase 3 is built on the
property they broke.

1. **`reconcileTo` was forward-only** (`subscription.ts`). The past-the-head gap it
   exists for requires moving the cursor *backwards*, so its `if (sequence <=
   applied) return` made the recovery a no-op in the only situation it was written
   for. Worse than a failed recovery: `queuedThrough` starts each attempt at
   `applied`, so with the cursor stuck high, every live event afterwards was
   discarded as already-queued — one gap reported, then permanent silence that
   reads exactly like a quiet thread. Fixed by adding `resetTo`, which moves in
   either direction and is deliberately a separate method.

2. **The backoff guard exempted its own failure path.** A fruitless attempt reset
   its streak on `synchronized`, and a handler-failure attempt synchronizes before
   it fails — so the one path the same iteration had just added was the one the
   backoff did not cover. Measured at 88 reconnects in 100 ms.

Phase 3's crash recovery assumes at-least-once delivery, which is exactly what
both defects violated. If either fix is wrong, Phase 3's cursor tests pass over a
transport that loses events.

## Three things to be adversarial about

- **Scenario B is recorded as `not-demonstrated` with a finding, not as a pass.**
  An interrupted turn settles, but the shell command it spawned runs to
  completion. Check the attribution: is it really below t3code
  (`CodexSessionRuntime.ts:2150-2180` forwards to the provider's own
  `turn/interrupt`), or is there something the client could have done?
- **The duplicated harness tables** in `harness-map.ts`. porch-driver must not
  import `agent-farm`, so the model-accepting set and the retired set are copied
  and asserted against the real ones by a test. Is the assertion actually
  load-bearing, or does it pass vacuously?
- **The evidence file's three states.** `demonstrated`, `not-demonstrated`,
  `failed`. Check that nothing reports `demonstrated` for a scenario whose
  assertion could not have failed.
